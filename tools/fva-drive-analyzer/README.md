# FVA Drive Analyzer — تحلیل‌گر فقط‌خواندنی درایو برای FarsiVoiceAI

ابزاری با کتابخانه استاندارد پایتون (بدون نیاز به `pip install`) که کارهایی را انجام می‌دهد که من از داخل کانکتور درایو **نمی‌توانستم** انجام دهم:

| محدودیت من | راه‌حل این ابزار |
|---|---|
| داخل `zip/tar` را نمی‌دیدم | فهرست داخلی آرشیو را می‌خواند (بدون استخراج) |
| سند بلند برایم بریده می‌شد و خواندن از وسط نداشتم | فایل را جریانی (تکه‌های ۶۴KB) از اول تا آخر می‌خواند |
| هش واقعی نداشتم | SHA-256 جریانی با کش، برای کاندید تکراری واقعی |
| شمارش دستی صفحه‌به‌صفحه | شمارش خودکار + کنترل تطابق (جمع بخش‌ها = کل فایل‌ها) |
| `shared=true` شمارش سروری نداشت | در حالت JSON دقیقاً از روی فیلد هر ردیف شمرده می‌شود |

## صادقانه: این ابزار چه چیزی نیست

- به Google Drive **وصل نمی‌شود** (در محیط من نه اعتبارنامه هست نه دسترسی شبکه به گوگل). روی یکی از این دو کار می‌کند:
  1. **کپی محلی درایو**: دانلود پوشهٔ درایو، یا Google Drive for Desktop، یا `rclone copy`/mount — بهترین حالت، چون محتوا و هش واقعی در دسترس است.
  2. **فایل JSON فهرست درایو**: خروجی صفحه‌بندی‌شدهٔ Drive API/کانکتور — فقط متادیتا؛ در این حالت همه فایل‌ها از نظر محتوا «خوانده نشد» می‌خورند و اطمینان هیچ‌وقت «بالا» نمی‌شود.
- صوت/ویدیو را گوش نمی‌دهد، روی عکس OCR نمی‌زند، محتوای اعضای داخل آرشیو (و آرشیو تو در تو) را باز نمی‌کند.
- `rar/7z` را فقط اگر `bsdtar` یا `7z` یا `unrar` روی سیستم باشد فهرست می‌کند؛ وگرنه صادقانه «نامشخص» می‌نویسد. (`0.rar` شما همین وضعیت را خواهد داشت مگر یکی از این‌ها نصب شود.)
- PDF را با `pypdf` (اگر نصب باشد) یا دستور `pdftotext` می‌خواند؛ PDF اسکن تصویری «بدون لایه متن» گزارش می‌شود.

## ایمنی (همان اصول مرحله ۰)

- **فقط‌خواندنی روی منبع**: هیچ حذف/جابه‌جایی/تغییرنام/ویرایشی در کد وجود ندارد.
- پیوند نمادین و فایل ویژه (FIFO/socket/device) در درخت منبع **دنبال یا باز نمی‌شود** و فقط یک ردیف «خوانده نشد» می‌گیرد؛ پس نام بی‌خطر یک symlink نمی‌تواند ابزار را به خواندن هدف حساس بیرون درخت وادار کند.
- پوشه خروجی **نباید داخل پوشه منبع باشد** (ابزار رد می‌کند) تا گزارش‌ها داخل پوشه سینک‌شدهٔ درایو ریخته نشوند. اگر در مسیر گزارش از پیش یک symlink باشد، نوشتن روی هدف آن انجام نمی‌شود.
- عضو آفیس/EPUB پیش از خواندن با حجم اعلام‌شده و در خواندن جریانی سقف دارد تا سند فشرده مخرب حافظه را بدون سقف مصرف نکند.
- فایل حساس (نام/مسیر شامل `takeout`، ‏`.env`، ‏`settings.cfg`، ‏`token/secret/credentials` و پسوندهایی مثل `.pem/.key/.mbox` — همه در `keywords.json`):
  - اصلاً **باز نمی‌شود**، هش هم نمی‌خورد، آرشیوش فهرست‌برداری نمی‌شود؛ فقط «حساس» می‌خورد و می‌رود بخش «د».
- از هیچ فایلی **تکه‌متن (snippet) چاپ نمی‌شود**؛ شاهد فقط نام کلیدواژه است.
- تکراری فقط وقتی **هش + حجم** یکسان باشد «کاندید تکراری» می‌شود؛ هم‌نامی کافی نیست و حذف پیشنهاد نمی‌شود.

## قواعد بخش‌بندی و اطمینان

- **بالا** فقط وقتی متن فایل تا انتها واقعاً خوانده شده باشد.
- فقط از روی نام/مسیر یا نام اعضای آرشیو: حداکثر **متوسط**.
- فایل **خوانده‌نشده هرگز «نامرتبط» نمی‌شود**؛ می‌رود «د» (یا با سرنخ قوی نام، «ب»).
- الف (مرتبط قطعی) فقط با شاهد محتوای خوانده‌شده؛ آرشیو با فهرست داخلی قوی حداکثر «ب».
- کلیدواژه‌های قوی/ضعیف در `keywords.json` قابل ویرایش‌اند؛ کلیدواژه کمکی به‌تنهایی دلیل قطعی نیست.

## اجرا

```bash
# حالت ۱: کپی محلی درایو
python3 fva_analyze.py "/path/to/My Drive" --out "/path/to/fva_report" \
    --expected-files 216 --expected-folders 61

# حالت ۲: فهرست JSON درایو (شکل connector/API، دارای فهرست files)
python3 fva_analyze.py inventory.json --out "/path/to/fva_report"
```

گزینه‌های مهم: `--files-only` ‏| ‏`--offset/--limit` (اجرای دسته‌ای با شمارنده) ‏| ‏`--no-hash` ‏| ‏`--hash-max-mb` ‏| ‏`--max-content-chars` ‏| ‏`--pdf-pages` ‏| ‏`--config keywords.json`

**اجرای دسته‌ای:** هر بازه را با یک پوشه `--out` جداگانه اجرا کنید؛ نام خروجی‌ها ثابت است و اجرای بعدی در همان پوشه گزارش قبلی را بازنویسی می‌کند. در اجرای ناقص (`partial`)، دو گزارش سراسری `duplicate_candidates.csv` و `empty_folders.csv` عمداً ساخته نمی‌شوند، چون از روی یک بازه ناقص می‌توانند گمراه‌کننده باشند.

در Termux هم با پایتون سیستم اجرا می‌شود:

```bash
python3 fva_analyze.py ~/storage/shared/MyDriveCopy --out ~/fva_report
```

## خروجی‌ها (همه داخل پوشه `--out`)

| فایل | محتوا |
|---|---|
| `FVA_relevance_map_2026-10-23.csv` | نقشه اصلی مرحله ۱ — ستون‌ها دقیقاً: نام، شناسه، مسیر فعلی، نوع، حجم، تاریخ ویرایش، اشتراکی؟، قابل‌خواندن؟، بخش، اطمینان، دلیل (با شاهد) + ستون‌های کمکی |
| `archive_contents.csv` | فهرست داخلی آرشیوهای غیرحساس |
| `duplicate_candidates.csv` | گروه‌های هش‌یکسان (فقط گزارش؛ فقط اجرای کامل) |
| `unread_and_sensitive.csv` | خوانده‌نشده‌ها و حساس‌ها |
| `empty_folders.csv` | پوشه‌های خالی (فقط اجرای کامل) |
| `summary.md` | شمارش و تطابق، جمع بخش‌ها، خوشه‌های سرنخی، بزرگ‌تر از ۱۰۰MB، محدودیت‌های همین اجرا |
| `state.json` | شمارنده پردازش برای ادامه‌دادن دسته‌ای |
| `.fva_hash_cache.json` | کش هش (اجرای بعدی سریع‌تر) |

نکته حالت محلی: شناسه با پیشوند `local-` ساخته می‌شود (شناسه درایو نیست) و ستون «اشتراکی؟» صادقانه **نامشخص** است، چون از فایل‌سیستم محلی معلوم نمی‌شود. برای شناسه و اشتراکی دقیق، حالت JSON را هم جداگانه اجرا کنید.
